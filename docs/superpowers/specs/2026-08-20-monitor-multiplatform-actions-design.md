# 多平台监控与处理动作设计

## 目标

优化桌面端与远程网页端的监控功能，使用户可以监控 YouTube 或 TikTok 公开账号，并为每个监控独立选择新视频的处理方式：

- 仅下载
- 下载并剪辑
- 下载、剪辑并发布

监控发现新视频后，必须保证同一监控、同一视频不会重复入队；下载、剪辑、发布任一阶段失败时保留已有产物，并给出下一步可操作的状态。

## 范围与边界

支持的来源：

- YouTube 频道或用户主页，例如 `https://www.youtube.com/@creator/videos`
- TikTok 公开账号主页，例如 `https://www.tiktok.com/@creator`

本次不支持单条视频链接、合集、私密账号或需要登录才能访问的账号页面。来源发现继续使用本地 `yt-dlp`，不引入平台 API 密钥和新的后台服务。

## 统一数据模型

监控记录持久化在 `~/AntBot/monitors.json`，新增字段：

```js
{
  sourceType: 'youtube' | 'tiktok',
  sourceUrl: String,
  processMode: 'download' | 'edit' | 'publish'
}
```

已有记录迁移规则：

- 根据 `sourceUrl` 自动补齐 `sourceType`；
- 没有 `processMode` 的旧监控迁移为 `publish`，保持原先“下载后继续剪辑并发布”的行为；
- 新建监控默认 `processMode: 'download'`，避免首次配置时意外消耗 AI/音色资源或触发发布。

监控覆盖配置继续沿用现有结构，发布平台、话题、风格、音色、原创和活动只在对应处理动作需要时使用。

## 发现与去重

新增统一来源适配器 `fetchSourceVideos(sourceType, sourceUrl, limit)`：

- YouTube 和 TikTok 都通过 `yt-dlp --flat-playlist -J --playlist-end 10 --skip-download` 获取列表；
- YouTube 沿用现有 cookies；TikTok 沿用下载器已有的 cookies 能力，公开页面不强制登录；
- 标准化视频信息：`id`、`title`、`url`、`webpageUrl`、`uploadDate`、`timestamp`、`duration`；
- 内部去重键为 `${sourceType}:${videoId}`，避免两个平台的同名 ID 互相冲突；
- 首次检查只建立最近视频基线，不自动处理历史视频；
- 后续仅处理未出现在 `seenIds` 的视频；
- 只有任务成功入队后才写入 `seenIds`，检查或入队失败时下次继续尝试；
- 同一监控检查过程保持互斥，删除或停用监控后不再继续入队。

## 任务处理流水线

监控任务继续复用 `TaskRunner`，不另建一套下载/剪辑/发布实现。监控服务把 `processMode` 写入任务快照，任务运行器按模式选择阶段：

```text
download  → 下载 → 完成
edit      → 下载 → 字幕/配音准备 → 视频合成 → 完成
publish   → 下载 → 字幕/配音准备 → 视频合成 → 发布 → 完成
```

具体行为：

- `download`：下载完成后将视频保存为稳定输出文件，任务显示“下载完成”，可打开目录；
- `edit`：下载成功后执行现有剪辑流程，成品视频保存为稳定输出文件，不调用发布模块；
- `publish`：执行完整流程，发布平台使用监控覆盖配置，未设置时回退全局默认；
- 剪辑或发布失败但已有视频产物时，状态为“部分完成”，保留 `outputPath` 并允许后续重新处理/重新发布；
- 仅下载模式不执行 AI 识别、Voicebox 或发布桥接；
- 发布模式遇到全局发布开关关闭时，不假装发布成功，保留成品并显示明确的未发布原因。

任务记录增加可见的处理模式和来源平台信息，历史、持久化任务和远程任务状态保持一致。

## 桌面端交互

监控页标题改为“视频监控”，说明文案同时覆盖 YouTube 与 TikTok。新增/编辑弹窗包含：

1. 平台切换：YouTube / TikTok；
2. 账号主页链接；
3. 监控频率；
4. 处理动作三选一，使用带说明的选项卡；
5. 发布平台、话题、活动、原创、风格和音色等高级配置。

列表卡片展示来源徽标、账号链接、处理动作、频率、最近检查、发现/入队统计和最近错误。卡片操作保留立即检查、编辑、启用/停用和删除，并在检查中显示进行状态，避免用户重复点击。

## 远程网页端交互与接口

远程网页端提供与桌面端一致的监控配置，不要求用户回到桌面端设置。复用现有远程认证和 SSE 通道，新增监控状态事件。

接口约定：

- `GET /remote/monitors`：获取监控列表；
- `POST /remote/monitors`：新增监控；
- `PATCH /remote/monitors/:id`：更新配置；
- `DELETE /remote/monitors/:id`：删除监控；
- `POST /remote/monitors/:id/check`：立即检查；
- `POST /remote/monitors/:id/toggle`：启用或停用。

远程页面新增来源平台和处理动作选择。保存后立即刷新卡片；立即检查期间按钮禁用并显示进度；错误以卡片内提示和 Toast 双重反馈。内置远程 HTML 与当前本地热更新缓存同步，避免桌面端继续读取旧页面。

## 错误与恢复

- 来源链接校验失败：保存前提示对应平台要求；
- `yt-dlp` 不存在或执行失败：不更新 `seenIds`，卡片展示最近错误，并允许立即重试；
- 任务入队失败：不更新 `seenIds`，下次检查继续处理；
- 下载失败：任务显示失败，可通过主控任务重试；
- 剪辑失败：保留下载文件并显示部分完成；
- 发布失败：保留成品视频，支持远程或桌面端重新发布；
- 检查完成后无新视频：更新时间和成功状态，但不增加入队统计。

## 验证策略

实现后进行以下验证：

- Node.js 语法检查：监控服务、IPC、任务运行器和渲染模块；
- 远程 HTML 内嵌脚本编译检查；
- 监控数据迁移与旧记录字段兼容性检查；
- `yt-dlp` 参数构造、来源校验和去重逻辑的静态检查；
- `git diff --check`；
- 按 `docs/packaging.md` 的 9 进制版本规则递增版本，构建 macOS arm64 `.app`，核对版本号、产物路径和签名。

不在本次范围内：远程页面 GitHub 仓库发布、TikTok 私密内容登录流程、平台官方 API 接入。
